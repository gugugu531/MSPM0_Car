# 纯 S 曲线滚球控制（基线）

本工程保留一条**前馈主导**的滚球控制路线，与原有的
`middleware/ball_balance`（反馈主导）并存；前者用于第三题正式入口，后者保留为设备调试入口。

| | `Device Check / H3 Static PID` | `H3 Challenge`（本文） |
|---|---|---|
| 模块 | `middleware/ball_balance` | `middleware/ball_scurve` |
| 哲学 | 反馈主导，每拍由误差算倾角 | 前馈主导，一次规划五次剖面 |
| 视觉时延 | 直接进入闭环相位 | 只影响残差修正 |
| 低速捕获 | 只诊断卡住 | 单向渐增脱困，进入 2 mm 后快速撤销 |

## 为什么前馈主导

球对倾角是**无阻尼双积分器**，位置扰动响应幅值 = `K_G·α/ω²`。球以速度 `v`
通过波长 `λ` 的表面起伏时 `ω = 2πv/λ`，因此表面缺陷的影响按 **1/v²** 衰减：

| v (mm/s) | λ=8 mm | λ=20 mm | λ=40 mm |
|---:|---:|---:|---:|
| 10 | 0.99 | 6.19 | 24.8 |
| 20 | 0.25 | 1.55 | 6.19 |
| **60** | **0.03** | **0.17** | **0.69** |

（坡度幅值 0.5°，单位 mm。）能量判据给出的**逃逸速度**为 20~50 mm/s。
所以：**滚动中的球基本不受凹槽缺陷影响，模型可信，应当把权重放在前馈上。**

代价在末端：五次剖面的速度二阶趋零，球会在低速区被局部凹陷俘获，
这就是本基线的固有落点误差下限。**不修，留作对照。**

## 控制链路

```
视觉 x, v ──► BallScurve_PlanTo(x, v, target)   一次规划，之后按时钟推进
                     │
                     ▼
              x_ref, v_ref, a_ref
                     │
   ┌─────────────────┼──────────────────┐
   │                 │                  │
θ_bias           asin(a_ref/K_G)   Kp·(x_ref−x) + Kd·(v_ref−v)
（水平点标定）      加速度前馈          剖面跟踪反馈（限幅 ±2°）
   │                 │                  │
   └────────► θ_cmd ◄┴──────────────────┘  + θ_roll·sign(v_ref)
                     │
              限幅 / 斜率限制
                     │
              查表 θ → cnt
                     │
              StepMotor_MoveToCount
```

## 关于"物理换算不准"

本任务**不假设**任何换算是准的。三个可疑换算及其应对：

| 换算 | 为什么可能不准 | 应对 |
|---|---|---|
| `K_G = (5/7)g` | 管身扭转、球非实心、接触点偏移 | 只用于前馈幅值，偏差由反馈吃掉 |
| 查表 `cnt→deg` | 尺寸测量误差 | 同上，且是单调映射，符号不会错 |
| **水平位计数** | 上电参考位重复性、装配公差、水管弯曲 | **必须辨识**，见下 |

第三条最要命：它是**常值倾角偏置**，在 T 秒移动里造成 `0.5·K_G·Δθ·T²`
的落点偏差——15 cnt（0.45°）、T=1.2 s 就是 40 mm。

### 一次 S 曲线移动就是一次辨识实验

移动过程本身已经在 ±3° 内扫过倾角，因此**不需要另外设计标定动作**。
对遥测里的 `beam`（编码器经查表算出的实际水管角）和 `aest`（球加速度估计）
做最小二乘：

```
aest = K · (beam − θ₀)
  斜率 K  = 真实滚球增益
  零交点 θ₀ = 真实动力学水平角  ──►  填进 H3S_LEVEL_BIAS_DEG
```

只取球确实在滚动（`|v| > 20 mm/s` 且未 stuck）的样本，避开静摩擦死区。

`tools/visualizers/scurve_sim_plot.py` 的 `identify_gain()` 就是这段回归，
仿真验证：注入 15 cnt 水平误差 → 回归出 +0.444°（真值 0.446°）；
注入 K_G 0.75×、查表 1.15× → 回归出 6041（真值 6041）。

## 实机辨识结果（2026-07-31，COM16）

三轮串口抓取（共约 5500 行 `[SCV]`）得到的硬数据，后续所有参数都据此定：

| 量 | 值 | 怎么得到的 |
|---|---|---|
| 真实滚球增益 `K_G` | 6000~7200 mm/s²/rad | 对 808 个滚动样本回归 `a = K(beam−θ₀)`，R=0.54 |
| 名义 `K_G` 偏差 | ±15% 以内 | 同上；**在容差内，不必改** |
| **静态脱离角 `θ_stick`** | **≈ 0.62°** | 球停在 −36.9 mm、目标 −50 mm，控制器持续给 −0.620°，**75 s 一动不动** |
| 纯 PD 残差下限 | **13.2 mm** | `θ_stick/Kp = 0.62/0.04711`，实测 13.1 mm |
| 保持角随位置变化 | −0.62° @ −36.5mm，+0.23° @ −4.9mm | 多次静止驻留点；跨度 0.88° |
| 视觉时延 | 均值 45 ms，p95 ~70 ms | `age` 字段 |
| 相机帧率 | 35 fps | `fps` 字段 |
| 端部视觉劣化 | `|x|>100mm` 时无效帧率是中心的 **58 倍** | 按 `xr` 分箱统计 |

### 由此得到的核心结论

> **不破静摩擦，±10 mm 判据在这台机器上数学上不可达。**
> 死区 13.2 mm 与增益整定、扰动大小、执行器带宽都无关。

## 小误差静止积分

当前积分器只解决“距离目标已经很近、但静摩擦让球停住”的末端残差，不参与
S 曲线移动段，也不跨航段保存：

| 条件 | 默认值 |
|---|---:|
| 剖面结束且目标误差 | `2 mm < |e| <= 15 mm` |
| 视觉运动标志 | `MOVING=0` |
| 速度可信且测量龄 | `V_VALID=1` 且 `age <= 120 ms` |
| 开始/继续积分的速度 | `|v| <= 3 mm/s` |
| 积分增益 | `0.08 deg/(mm*s)`，积分器自身不设额外倾角上限 |

积分律为 `I += Ki * (target-x) * dt`。进入 `|e|<=2 mm`、视觉报告
`MOVING=1`、`|v|>=5 mm/s`、开始新剖面或速度不可信时，都以 `8 deg/s`
快速把额外倾角退回 0。检测到运动且速度可信时，实际退积分速率为
`8 + 0.40*|v| deg/s`：球速越高，对积累倾角造成的额外加速补偿越强；PD 的速度项
同时继续产生反向制动。3/5 mm/s 两个阈值形成迟滞，避免速度量化噪声造成反复开关。

`2..15 mm` 区间只允许小积分工作；`>15 mm` 才允许单向脱困介入，并且必须等
残余积分角清零。因此两个额外倾角不会叠加。遥测 `iacc` 是积分角，`iact=1`
表示本拍正在累积；`ball_tune.html` 提供独立的“小误差积分量”曲线。

### 当前如何判断球是否移动

MCU 不自行从单拍位置差分生成 `moving`。树莓派视觉端在 UART `FLAGS.bit1`
写入 `MOVING`，`bsp/rpi_uart` 校验帧后原样传给控制器；`mv` 遥测即该标志。
小积分还要求速度有效、测量足够新且 `|v|<=3 mm/s` 才累积；清零则采用更宽松的
“`MOVING=1` **或** `|v|>=5 mm/s`”，避免上游标志延迟时继续蓄力。

## MOVE / BRAKE / HOLD 增益调度

### 为什么必须分开

一个容易误判的事实：剖面走完后（`act=0`、`ff=0`），控制律**已经**退化成绕固定
目标的纯 PD。所以问题从来不是"用移动的算法去做稳定"，而是——

> **稳定段用的是为移动段推导的增益。**

`Kp=0.04711 / Kd=0.03533` 来自 `wn=2.4, ζ=0.9`，那是为跟踪一条 90 mm/s、
200 mm/s² 的参考轨迹算的。守一个不动的点根本不需要这么大的微分增益。

两段的敌人完全不同：

| | MOVE | HOLD |
|---|---|---|
| 球速 | 60~90 mm/s，远超逃逸速度 | ≈0 |
| 主要敌人 | 轨迹跟踪误差、执行器带宽 | 静摩擦死区、饱和极限环 |
| 表面缺陷 | 按 1/v² 衰减，可忽略 | 主导 |
| 速度信号 | 有效信号 | 树莓派给整数 mm/s，多为量化噪声 |
| **Kd** | 提供阻尼，**必需** | **有害**：放大量化噪声、驱动饱和 |
| **Kp** | 跟踪刚度 | **直接决定静摩擦残差 θ_stick/Kp** |

### 实测证据

2026-07-31 抓取：剖面走完后仍有 6.42 rad/s（周期 0.98±0.04 s）、峰峰
17~28 mm 的**持续极限环**。分解指令角：

```
Kp·e = 0.04711 × 12 mm   = 0.57°
Kd·v = 0.03533 × 40 mm/s = 1.41°   ← 饱和的是这一项
合计 1.98° ≈ 限幅 2.000°
```

`fbc`（反馈限幅命中率）与极限环振幅单调相关，坐实了饱和驱动：

| `fbc` 占比 | 0% | 10% | 20% | 30% |
|---|---:|---:|---:|---:|
| 平均峰峰 | 17.4 mm | 21.8 mm | 23.1 mm | 27.7 mm |

### 当前设计

**只做增益调度，不做三套算法。** MOVE / BRAKE / HOLD 共用同一个 PD、限幅、
斜率限制和脱困状态，三个状态只给出不同的目标增益。`sched=0` 时严格回退到原固定
`kp/kd`，便于同一固件 A/B。

| 状态 | Kp | Kd | 目的 |
|---|---:|---:|---|
| MOVE | 0.04711 | 0.03533 | 保留当前轨迹跟踪参数 |
| BRAKE | 0.03000 | 0.03533 | 降低位置推动，给制动前馈和速度反馈留权限 |
| HOLD | 0.04711 | 0.02000 | 保留克服静摩擦的位置刚度，降低测速噪声放大 |

BRAKE 不按固定距离切换，而是比较保守停止距离与剩余距离：

```
vc    = sign(target-x) * v
dstop = max(vc,0)*brake_delay + max(vc,0)^2/(2*brake_acceleration)
```

`dstop/|target-x|` 从 `0.60` 到 `1.00` 时，BRAKE 权重经 smoothstep 从 0 升到 1，
再用 `0.08 s` 一阶滤波抑制视觉速度跳变。默认换向延迟 `0.22 s`、有效制动加速度
`120 mm/s²`，均可在整定台热更。

HOLD 仅在剖面结束、`|e|<=15 mm`、`|v|<=20 mm/s` 连续 `0.30 s` 后进入；
`|e|>=30 mm` 或 `|v|>=35 mm/s` 时退出，权重以 `0.25 s` 时间常数连续过渡。
速度可信时在 `age<=60 ms` 保持全权，至 `120 ms` 线性降到 `0.30`；速度不可信时
直接使用 `0.30`。200 ms 视觉超时仍由任务层执行就地保持。

⚠ **进入判据只看距离是不够的**：极限环里球在 −45 mm、目标 −50 mm，只差 5 mm
已经"很近"，却正以 40~70 mm/s 穿过。此时切到低 Kd 会让球直接飞过去。

⚠ **单向脱困不要求已进入 HOLD**：球若被钉在 20 mm 外，`|e|` 超过
`hold_enter_error_mm`、HOLD 永不成立，而那恰恰是最需要脱困的场合。
增益调度和脱困是正交机制，不互相作为前置条件。

⚠ 本仓库的主机仿真**无法验证这一项**——它针对的饱和极限环在仿真里复现不出来
（对树莓派侧测速滤波的建模过粗）。仿真里同步了这组配置只是防止两边悄悄分叉。

## 抖动（破静摩擦）

球对倾角是双积分器，位置响应幅值 `K_G·A/ω²` 随频率按 **ω⁻²** 衰减。于是可以
让管子抖得足以破静摩擦，而球几乎不动：

| 频率 | 指令幅值 | 实际幅值 | 电机峰值转速 | 球纹波 |
|---|---|---|---|---|
| 1.5 Hz | ±0.82° | ±0.6° | 47 deg/s | 0.83 mm |
| **2.0 Hz** | **±0.97°** | **±0.6°** | **74 deg/s** | **0.46 mm** |
| 3.0 Hz | ±1.28° | ±0.6° | 146 deg/s ✗ | 0.21 mm |

指令幅值要按步进位置环的一阶衰减反算：`实际 = 指令 / sqrt(1+(2πf·τ)²)`，
τ = 1/`STEP_MOTOR_SERVO_KP` = 0.1 s。3 Hz 超 120 deg/s 限速，所以窗口是 1.5~2 Hz。

**用 0.46 mm 的纹波换掉 13.1 mm 的死区。**

触发条件（三者同时满足并持续 `dither_dwell_s`）：

1. 剖面已走完（HOLD 段）；
2. 目标误差 > `dither_min_error_mm`（3 mm）；
3. 球速 < `dither_max_speed_mm_s`（8 mm/s）。

误差进入 3 mm 后自动停振——这同时提供了**捕获**：抖动破摩擦让球爬过去，
停振让摩擦把球锁在那里。

仿真验证（`kick` 场景，θ_stick 按实测 0.62° 配置）：

| 抖动指令 | 实际幅值 | 末段 \|误差\| |
|---|---|---|
| 关闭 | — | 5.74 mm |
| ±0.50° | ±0.31° | 5.57 mm |
| **±0.97°** | **±0.60°** | **1.71 mm** |
| ±1.40° | ±0.87° | 1.18 mm |
| ±2.00° | ±1.25° | 4.00 mm ← 过大反而变差 |

⚠ 仿真的 Karnopp 模型让基线只有 5.74 mm，而实机是 13.1 mm，所以仿真**低估了
基线问题**。方向和尺寸可信，绝对值以实机为准。

## 遥测

`[SCV]` 每 80 ms 一行，key=value，按数据流方向分组；当前约占 115200 UART 有效带宽的 72%：

| 组 | 字段 |
|---|---|
| 时基状态 | `t st wp ok` |
| 视觉层 | `xr x vr v aest age q` |
| 剖面层 | `tgt xref vref aref tp tpd act` |
| MOVE/HOLD | `hm hb kde` |
| 控制分量 | `bias ff rff fb iacc dith brka u` |
| 跟踪误差 | `ex ev etgt` |
| 执行器层 | `beam lag cnt cmd perr spd frq at` |
| 标志与链路 | `sat fbc rl iact dth brk set mv vv px edge deg hold guard fps gap inv crc drop` |

`fbc`（PD 分量被 `feedback_limit_deg` 夹住）和 `dth`（抖动注入中）是后加的：
早期版本只有 `sat`（物理角度范围），导致 45% 的反馈限幅在遥测里完全隐形。

`gm` 是 MOVE/BRAKE/HOLD（0/1/2），`bb`/`hb` 是 BRAKE/HOLD 混合权重，
`kpe`/`kde` 是本拍生效增益；`ds`/`vc` 是停止距离与朝目标速度，`vw` 是速度权重。

### 判读顺序

排查时按这个顺序看，每一步的判据都是明确的：

1. `gm/hb/kde` —— 是否进入 HOLD，`kde` 期望停在 0.020 附近；
2. `fbc` —— 反馈还饱不饱和？期望 ≈0%；
3. `|v|` —— 极限环消失了吗？期望 `|v|<3` 占比接近 100%；
4. `dth` —— 球停住之后抖动起来了吗？期望开始出现 1；
5. `etgt` —— 落点是否从 ~13 mm 向 0 收敛。

⚠ 第 3 步成功后、第 4 步生效前，球会先停在约 13 mm 外，**看起来比极限环
状态更差**（极限环让球持续运动，反而有 75.9% 的时间落在 ±10 mm 内）。
那是中间态不是失败，判据要看 `dth` 有没有起来，而不是马上看落点。

进入任务时另有四行 `[SCVCFG]` 打印全部换算与整定参数，日志自带上下文。

**定位问题的第一梯队**：
- `lag = u − beam`：指令角与实际角之差，**步进跟不上的直接指标**；
- `ex`：剖面跟踪误差，大 = 前馈不够或执行器跟不上；
- `etgt` 与 `stuck`：末端落点误差与是否被摩擦钉住；
- `bias`：当前用的水平点标定值，为 0 说明还没标定。

## 主机端仿真

```bash
cd tools/checks
gcc -O2 -std=c11 -I../../middleware/ball_scurve \
    -o sim_ball_scurve sim_ball_scurve.c ../../middleware/ball_scurve/ball_scurve.c -lm
```

仿真器**直接链接固件源码**，跑的就是上板的控制律。单次运行约 **27 ms**。

### 两种调用形式

```bash
# 位置形式（保留，兼容 scurve_sim_plot.py）
./sim_ball_scurve real 10 120 2.4 0.9 0.97 2.0 0 0.020 0.020 0

# 命名形式：对象参数也能改，不用重新编译
./sim_ball_scurve --scenario=kick --servo-kp=10 --hold-kd=0.020 \
                  --stick=0.62 --bow=0.8 --backlash=2.5 --vel-alpha=0.10 --seed=7
```

命名参数在**场景预设之后**施加，可覆盖预设的任何一项。两种形式已验证**逐位一致**。

| 组 | 参数 |
|---|---|
| 场景/种子 | `scenario` `seed` |
| 对象 | `bow` `rough` `stick` `stick-var` `roll` `viscous` `level-err` `gain-scale` `linkage-scale` `backlash` |
| 测量 | `vis-noise` `vis-lag` `vis-bias` `vel-alpha` `ideal-meas` |
| 控制器 | `servo-kp` `speed-limit` `wn` `zeta` `dither-amp` `dither-hz` `pd` `hold-kd` `move-ki` `int-seed` |

场景：`ideal | gain | vision | bow | stick | level | real | kick | ab`。
`pd=1` 跳过剖面（参考量钉在目标点），控制律精确退化为纯 PD——用于同代码/同对象的严格 A/B。

`--seed` 换的是**表面实现**（粗糙度相位 + 静摩擦空间分布 + 噪声流）。此前所有
仿真结论都建立在单一固定种子上，控制参数有可能只是恰好贴合那一条表面；
现在可以跑多种子看分布。

### 用它做了什么：两个假设，一个被否定

**假设 A：机械回差是极限环的成因 —— 否定。**

新增 `backlash_counts` 建模（编码器在电机上，**看不见**回差）。扫 0~8 计数：

| 回差 | 保持段峰峰 | `\|v\|<3` |
|---|---|---|
| 0 ~ 8 cnt | 0.00 mm | 100% |

球被静摩擦钉住，回差完全无影响。

**假设 B：树莓派测速滤波的时延 —— 支持，但不完整。**

`vision_velocity_alpha` 此前硬编码 0.35。扫描后：

| alpha | 等效 τ | 保持段峰峰 | `\|v\|<3` |
|---|---|---|---|
| 0.05 | 0.50 s | 78.3 mm | 3% |
| **0.10** | **0.25 s** | **22.3 mm** | **5%** |
| 0.20 | 0.13 s | 0.7 mm | 97% |
| 0.35（原假设） | 0.07 s | **0.00 mm** | **100%** |

**alpha=0.10 精确复现了实机工况①**（极限环 17~28 mm、`|v|<3` 2~8%），
而原先的 0.35 给出完全静止——这就是仿真一直复现不出极限环的原因。

⚠ **但它不能同时满足另外两个工况**：

| 工况 | 实机 | 仿真 @ alpha=0.10 |
|---|---|---|
| ① KP=10 无 HOLD | 峰峰 17~28 mm | **22.9 mm ✓** |
| ② KP=10 + HOLD | 峰峰 0.50 mm、`\|v\|<3` 100% | 24.4 mm、27% ✗ |
| ③ KP=3 | 振铃后驻留 13.1 mm | 峰峰 124.9 mm ✗ |

**单参数拟合不成立。** 于是直接从实机数据测这个滤波，而不是从仿真反推。

### 直接测量推翻了假设 B

极限环段是频率已知的准正弦，可以在该频率上同时测相位差和幅值比，
用一阶模型两路独立反解 τ 并交叉验证（`scratchpad/vel_lag.py` 的方法）：

```
主频 ω = 6.41 rad/s
vr 相对 d(xr)/dt 的相位滞后   21.8°
幅值比                        0.963
τ(相位法) 62 ms   τ(幅值法) 44 ms   ← 两法一致 ⇒ 一阶模型成立
折算 40 fps 一阶系数 alpha ≈ 0.286
```

**树莓派测速只滞后约 50 ms，不是仿真反推的 250 ms。** 原先硬编码的 0.35
（τ=71 ms）几乎是对的。假设 B 被实测推翻。

### 假设 C：MSPM0 侧的位置外推 —— 存在，但同样不是成因

数据核对确认控制器用的是 `x = xr + v·age` 而非 `xr`：

| 数据段 | `x−xr` RMS | `x−(xr+v·age)` RMS | 外推项幅值 |
|---|---:|---:|---:|
| 极限环段 | 1.519 mm | **0.221 mm** | 1.54 mm（位置标准差的 28%） |
| 稳定段 | 0.000 mm | 0.024 mm | 0.024 mm |
| KP=3 段 | 3.927 mm | 0.225 mm | 3.94 mm |

残差就是 `v`（整数 mm/s）与 `age`（整数 ms）的量化。这条路径此前**完全没有
建模**——它把一个带 62 ms 滞后的速度乘上龄期后加回位置，是环路里一条额外的
反馈通道。已连同速度的整数量化一起补进仿真（`--extrap` / `--vel-quant`）。

但打开它之后极限环仍然不出现（峰峰恒为 0.00 mm）。

### 结论：三个假设全部排除，仿真仍复现不出极限环

| 假设 | 结果 |
|---|---|
| A 机械回差 | 否定（0~8 cnt 无任何影响） |
| B 测速滤波时延 250 ms | **实测推翻**（真值 62 ms） |
| C 位置外推 + 速度量化 | 存在且已建模，但对极限环无影响 |

**剩下的最可能原因是模型结构而非参数**：当前用的 Karnopp 摩擦是二值
stick/slip，球一旦卡住就**绝对静止**。真实的预滑移摩擦（Dahl/LuGre）在
"卡住"状态下仍有微米级蠕变，球会缓慢漂出静摩擦带，控制器持续追赶——
这正是极限环需要的能量注入通道。**二值模型在结构上就产生不了观测到的行为。**

其它未排除的候选：`STEP_MOTOR_SERVO_RESUME_COUNTS=6` 的回差带（未建模）、
视觉检测噪声与球速相关（运动模糊）、树莓派测速可能根本不是滤波差分。

手工逐条假设已经到头（三条全是死路）。要继续就需要在多维空间里做联合辨识，
且试验台要改成**回放实机指令序列**而非用 `kick` 的速度冲击近似。

## 仿真结论

O→+5cm→−5cm 序列，末端相对 −50 mm 的落点误差：

| 场景 | 巡航段跟踪 RMS (KP=3 → 20) | 末端落点误差 (KP=3 → 20) |
|---|---|---|
| 理想对象 | 8.80 → **1.34** mm | 0.01 → 0.41 mm |
| 换算不准 K_G−25% | 11.27 → **1.63** mm | 0.46 → 0.03 mm |
| 测量链 55 ms 时延 | 28.73 → **9.60** mm | −3.69 → −1.09 mm |
| 水管弯曲 1.5 mm | 17.05 → 5.49 mm | −15.51 → **−14.68** mm |
| 静摩擦 0.30° | 11.58 → 2.98 mm | 4.26 → **6.99** mm |
| 水平点偏 15 cnt | 20.60 → 8.88 mm | −7.01 → **−9.20** mm |
| 全部叠加 | 24.97 → 10.35 mm | −35.60 → **−23.42** mm |

三条结论：

1. **`STEP_MOTOR_SERVO_KP = 3.0` 是巡航段的主导误差源。** 位置环是一阶滞后，
   时间常数 `1/KP = 333 ms`，跟踪移动的角度指令时落后 `θ̇/KP`，实测峰值滞后
   达 **3.3°**（指令峰值才 3.2°）。提到 20 后滞后降到 0.39°，跟踪 RMS 降 6.6 倍。
   转速上限不是瓶颈（60 与 120 deg/s 结果几乎相同）。
2. **换算不准基本无害。** K_G 偏 25%、查表偏 15% 时巡航 RMS 1.63 mm、末端 0.03 mm，
   反馈完全吸收得掉。
3. **剩下的全是偏置型误差**，纯 S 曲线按设计消不掉：弯曲 −14.7 mm、
   水平点 −9.2 mm、静摩擦 +7.0 mm，叠加后 −23.4 mm。这正是弯曲前馈
   `θ_bow(x)`、水平点标定和低速捕获段要解决的部分。

## 步进位置环增益的实机整定

`STEP_MOTOR_SERVO_KP` 从 3.0 改到 **10.0**，依据见 `bsp/step_motor/step_motor.h`
的注释。摘要：

- **KP=3 的证据**：实测 `|spd| = 0.54×|perr|`，最大只到 58.9 deg/s，而
  `SetSpeedLimit(120)` **从未被触及**——转速被 KP 卡死，限速是死代码。
  位置环 τ=1/KP=333 ms，在振铃频率 3.3 rad/s 上独占 47° 相位，
  而裕度预算只有 ~68°，余下 ≈3°，对应 ζ_eff≈0.07。
- **KP=10 的验证**：`|spd|` 峰值达到 120.0（限速终于成为约束），
  `lag` RMS 从 0.92° 降到 0.441°。
- **副作用**：出现一个 6.6 rad/s 的极限环，但**不是自激**——
  75 s 无扰动采集中 `|v|<3mm/s` 占 100%、漂移 0.9 mm、限幅命中 0%。
  只有大扰动才能触发，比赛场景下扰动可控，因此保留 KP=10。
- **末端抖动的原顾虑不成立**：静置段计数活动几乎不随 KP 变化（37→50 cnt/2s），
  由 `SERVO_RESUME_COUNTS`(6) 的回差带挡着，与 KP 解耦。

## 已知未修

1. **移动段启动 overshoot**：规划那一刻水管正处在保持角（如 −0.615°），
   而前馈假设它在 0°。水管要 360 ms 才转过去，这期间球先朝反方向滚
   8 mm，跟踪误差让 `fb` 打满 ±2°，指令角冲到 3.46°（剖面前馈峰值的 2.1 倍），
   球被加速到 214 mm/s（规划峰值 89 mm/s）。
   实测两次：−54.5 → 冲到 +52.7；−68.5 → 冲到 +48.7。
   **修法**：规划时把当前实际水管角作为该段初始偏置。
2. **端部视觉劣化**：`|x|>100mm` 时无效帧率是中心的 58 倍，`age` 逼近
   200 ms 断链阈值，任务会掉进 DEGRADED。要在树莓派侧解决。
3. **位置外推越界**：`RpiUart` 的外推在丢帧期间会给出 `|x|>123.5mm`
   的物理上不存在的位置，应夹在水管半长内。
