# 分层架构

## 分层规则

工程源码采用单向依赖结构：

`app -> core -> middleware -> bsp`

上层可以调用下层公开接口，下层禁止包含或调用上层头文件。

## 模块职责

- `app`：固件入口、中断分发、启动页、菜单、任务流程和设备自检页面。
- `core`：控制算法、运动学、PID、巡线策略、传感处理和云台视觉控制。
- `middleware`：共享运行时状态、系统时间、延时服务、错误处理、底盘电机组合初始化、云台组合初始化。
- `bsp`：直接面向板级外设的驱动，包括电机、编码器、OLED、按键、激光串口、IMU、步进电机和巡线传感器。

## 支撑目录

- `board`：SysConfig 生成文件、输入文件和启动/链接资源。生成文件内容不手写业务逻辑。
- `project`：CCS 和 Keil 工程元数据。
- `tools`：调试、烧录和诊断脚本。
- `docs`：架构、接口、变更记录、待办和构建说明。

## 依赖边界

- `bsp` 只能包含标准头、厂商/板级头和 `bsp` 内部头文件。
- `middleware` 可以包含 `middleware` 和 `bsp` 头文件。
- `core` 可以包含 `core`、`middleware` 和 `bsp` 头文件。
- `app` 可以包含任意下层公开头文件。
- 跨模块共享状态默认放在 `middleware/runtime`；如果状态由某个外设驱动直接维护，则由对应 `bsp` 头文件导出。
