# H3 450 帧控制数据分析与整改

数据源：`captures/h3/h3_20260731_envelope.csv`，有效 450 帧，设备时间跨度 27.048 s。

## 结论

这轮极限环不是串口或树莓派坐标失真造成的。CRC、Debug 丢字节均为 0，遥测周期中位数
60 ms；主要问题是执行器模型单位错误和速度包络结构无效。

| 指标 | 实测结果 | 含义 |
|---|---:|---|
| 位置范围 | -49.85 ~ +33.64 mm | 未收敛到中心 |
| 目标过零次数 | 29 | 持续极限环 |
| 目标过零速度中值 | 110.3 mm/s | 过零动能过大 |
| 末段速度 RMS | 80.22 mm/s | 后段仍未衰减 |
| 位置极值绝对值中值（前/后 10 个） | 41.2 / 31.1 mm | 仅缓慢衰减 |
| `esrc=1` | 0/450 | 旧制动包络从未接管 |
| `vb/vc` 最小值 | 2.33 | 旧公式在有效行程内结构性失效 |
| 停止面翻向到水管过零 | 中值 153 ms | 明显慢于旧模型 |
| 停止面翻向到球速过零 | 中值 770 ms | 制动响应很迟 |
| 实际/预测停止行程 | 56.7 / 17.8 mm | 旧模型低估约 3.04 倍 |

`StepMotor_SetSpeedLimit(60)` 的单位是电机编码器轴角速度。由连杆 LUT 可知中心附近
20 count 对应约 3.6° 电机轴角、但只有约 0.59° 水管角，因此水管速度约 10°/s；串口中
停止面翻向到水管过零所反推的速度中值为 11.4°/s，与 LUT 一致。旧控制器把 60°/s 直接
当成水管角速度，使换向距离严重低估。

旧 `vb=sqrt(2*a*|stop|)` 只描述已经处于稳态制动角后的距离，而且与基于同一 `stop` 的
tanh 曲线取小。当前参数下 `vb` 始终大于 `vc`，所以所谓 S 型包络实际退化为单一 tanh。

## 已实施方案

1. 保持电机轴限速 60°/s，但制动模型单独使用保守水管换向速度 10°/s。
2. 对通信延迟、当前顺向加速度、连杆换向和稳态制动求和；对固定方向可整理成
   `d(v)=A*v²+B*v+C`。
3. 用当前位置预算 `|e|/rho` 反解允许速度 `vb`。若连零初速换向也来不及（预算不大于 C），
   直接令 `vb=0`；否则取二次方程正根。
4. `vref=-sign(e)*min(vc,vb)` 始终朝 0 cm。球速超过动态包络时，速度内环输出反向倾角，
   形成加速—减速的反馈式 S 过程；外界扰动后每拍重新规划。
5. 保留 `stop/dstop/ddl/dsl/dss` 诊断，并新增 `dbud`（距离预算）、`dmin`（零初速换向仍需
   消耗的距离）。`esrc=1` 现在明确表示完整动态制动分支接管。

将新算法离线作用于原 449 个非启动样本，制动分支会在 365 帧（81.3%）接管，包络中值由
原先的 tanh 曲线约 37.0 mm/s 降到 22.7 mm/s；这只是同轨迹反事实回放，不能代替刷写后的
闭环实测，但证明新分支在数值上可达且会对本次高能极限环作出制动响应。

## 下一轮验收

刷写后至少记录 30 s：先自然收敛，再做一次拨动和一次短时截停。应同时满足：`esrc` 两个
分支均出现、目标过零速度逐周期下降、`dmin/dbud` 接近时 `vb` 降至零、无 CRC/drop 增长，
并重点比较位置极值包络是否单调缩小。若仍有固定偏置，再在进入低速稳定区后单独评估
`zero_trim`，不要用水平 count 或 safe return 掩盖动态问题。

## 动态包络固件实测与执行器提速

随后使用已包含 `dbud/dmin` 的新固件记录 `h3_20260731_postfix.csv`：582 帧、35.186 s。
`esrc=1` 达到 464/582，证明新制动分支已实际工作；相对旧记录，过零速度中值由
`110.3` 降至 `85.7 mm/s`，末段平均绝对位置由 `22.45` 降至 `17.50 mm`，末段速度 RMS
由 `80.22` 降至 `66.72 mm/s`。改善明确，但仍未进入 settled，极值约为负侧 `31.6 mm`、
正侧 `19.3 mm`，保持极限环。

新记录中，制动命令开始时球速中值仅约 `18.0 mm/s`，但命令到水管实际过零仍需中值
`244 ms`，到球速过零需 `785 ms`，期间实际停止行程中值约 `50.9 mm`。因此下一轮将电机
轴限速从 `60` 提高到 `90°/s`；按原实测连杆比例，水管模型先从 `10` 提高到保守
`13°/s`。本轮不同时修改 `eta=0.45`，避免无法区分执行器提速与动力学系数修正的贡献。

提速后应重新记录至少 30 s，首先验证水管过零延迟是否低于 `180 ms`，并检查编码器目标
误差、guard fault 和是否出现丢步。若执行器跟踪正常但滚球仍在换向阶段持续获得显著高于
模型的加速度，再根据实测约 `145 mm/s²/deg` 与模型约 `55 mm/s²/deg` 的差异单独修正
`braking_efficiency`。

12.014 s 的 90°/s 检查记录随后确认：电机轴速度 P95/峰值约 `75/87°/s`，guard 全程正常，
但命令制动到水管过零中值仍有 `219 ms`，目标过零速度中值升至 `96.6 mm/s`。因此瓶颈不再
只是电机限速，而是模型用同一个 `eta=0.45` 同时表示换向前继续加速和到位后的制动。

最终将两者拆开：前者取 `1.00` 以覆盖实测斜率，后者取保守 `0.60`，典型
`x≈28 mm、beam≈2.2°` 状态下最小换向距离由约 `8 mm` 提高到约 `19 mm`，允许速度由约
`25 mm/s` 压低到约 `9 mm/s`。在用户确认安全措施充分后，执行器进入高带宽档：电机轴
`120°/s`、端到端模型 `12°/s`、控制/制动角 `±4°`、制动目标角变化率 `100°/s`。物理
限位和 guard 不变，下一轮必须同时验证过零速度下降和编码器无失步。

对 120°/s 记录继续检查 TIMG6 路径：PWM 更新每 10 ms 先停计数器，再直接写 LOAD/CC，CC
采用 immediate update，随后重新启动；120°/s 仅需约 2133 Hz、ARR 约 28，远低于 5000 Hz
上限。实测轴速 P50/P95/峰值约 `48/93/126°/s`，而目标误差中值 74 count 经固定 `KP=3`
只会请求约 `40°/s`，与实测吻合。因此主要限制是位置伺服比例律而非寄存器装填。

H3 后续临时把位置伺服增益提高到 `6/s`，退出任务恢复全局默认 `3/s`。同时新增
`mspd/mkp/sf/arr/cc/ctr/sdt/smax` 遥测，使下一轮可逐帧验证 PWM 与调度；根据同轮回归
`a≈129×beam+50 mm/s²`，动力学零位初值设为 `-0.40°`，但进入 H3 仍保持当前实际位置，
不会执行到该角度的 safe return。
