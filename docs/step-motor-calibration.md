# 摆杆步进电机标定手册

全部标定在 `Main Menu -> Device Check -> Step Motor` 页完成，配合 Debug_Ex（UART1，
115200）的 `[SM]` 遥测。参数改完后重新编译烧录。

> 本文只管**硬件参数**（细分数、极性、编码器刻度、行程）。控制律、增益与整定流程见
> [`control-plan.md`](control-plan.md)。

## 页面结构

该页分六个模式，**ENTER 长按**循环切换，**BACK** 退出整页。标题栏显示当前模式
（如 `SM 4/6 HAND`）。**进页落在 `JOG`**——点动对位比标定常用得多；其余五个是标定模式，
每个只负责一到两项标定，并把该填回 `step_motor.h` 的那个数**直接算好显示出来**，
不用在现场心算。

| 模式 | 驱动器 | UP / DOWN 单击 | UP / DOWN 长按 | ENTER 短按 | 用途 |
|---|---|---|---|---|---|
| `1/6 JOG` | 通电 | **点动一步** ±（双击 2 步） | **步长 粗 / 细**（三档） | 就地停住 | 精确对位、实测水平位 |
| `2/6 RUN` | 通电 | 持续正转 / 反转 | — | **暂停**（保留读数） | DIR 极性、编码器方向 |
| `3/6 TURN` | 通电 | 目标圈数 ±1 | — | 开始（走满自动停）/ 中止 | 细分数 |
| `4/6 HAND` | **断电** | 已手转圈数 ±1 | — | 重设基准 | 编码器每转计数、EN 极性 |
| `5/6 SWEEP` | 通电 | 转速档 ± | — | 启动 / 停止本档 | 最大步进频率 |
| `6/6 SPAN` | **断电** | — | — | 交替打 A / B 点 | 行程限位、抬升目标、减速比 |

> 驱动只接受位置指令，所以页面里的"持续转"是**把目标设到很远处**实现的，各模式的
> "转速"实际是设给伺服的**速度上限**（误差大时饱和在上限上跑，效果等同匀速）。
>
> **限位全程有效**，这条路径同样受位置限幅约束：`RUN` 按住不放只会停在软限位上。
> `HAND` / `SPAN` 因此改为**断电手推**——失能后伺服不出力、守护也无从纠正，编码器却
> 照常计数，这是量机械行程唯一量得准的办法。
>
> `SWEEP` 在软限位内**往复**跑：摆杆装机后行程只有几百个计数，朝一个方向跑不到一秒
> 就抵住边界了，攒不出可判读的数据；往复还更接近摆杆的真实工况。

切模式会自动停机。进入 `HAND`/`SPAN` 自动断电（可手推），离开时自动恢复使能；
**退出整页时失能**——与上电即失能的策略一致，摆杆的保持力矩由后续任务显式申请。

### `JOG` 点动：步长与「最小移动角度」

`JOG` 用来把摆杆一步一步挪到某个位置，屏上四行是 `cnt`（编码器计数）、`step`（步长，
计数）、`sdeg`（这一步对应的电机轴角）和限位 / 守护状态。三档步长按到位容差派生：

| 档 | 计数 | 轴角 | 表达式 |
|---|---|---|---|
| 细 | 3 | **0.54°** | `2 × POSITION_TOLERANCE_COUNTS + 1` |
| 中 | 24 | 4.32° | 细档 × 8 |
| 粗 | 75 | 13.5° | 细档 × 25 |

双击走 2 步（1.08° / 8.64° / 27°）。中/粗两档的倍数是按**绝对步长**倒推的：软限位内可用
行程只有 ≈410 计数，粗档 75 让五六下能从一端走到另一端，中档 24 是「看得见但不过头」的
调整量。容差以后再变，这两档跟着变，倍数可能得重挑。

> **为什么是 `2 × 容差 + 1` 而不是 `容差 + 1`**：伺服从带外接近、一进带就停，所以停下来
> 时残余误差的量值 ≈ 容差，**符号与刚才的行进方向相同**（目标在前、实测在后）。正向
> 点完停在 `err = +容差`，此时按反向，新误差 = `+容差 − 步长`，量值只有 `步长 − 容差`。
> 要它还在容差带外，就得 `步长 − 容差 > 容差`，即 **步长 > 2 × 容差**。
>
> 取 `容差 + 1` 的话换向后 `|err|` 恰好等于 1 ≤ 容差，伺服判为已到位——**换向后的第一下
> 必然是死键**，而且是确定性的、不是偶发。这正是「换向第一下电机不动」这个现象的成因。
> 代价：换向后的第一下实际只走 `步长 − 容差`（细档 3 → 2 计数 = 0.36°），但**位置不累积
> 误差**，因为加的是目标而不是实测位置。

> **为什么最细一档不是「一个微步」**：一个微步是
> `STEP_ANGLE_DEG / MICROSTEP` = `1.8 / 32` = 0.05625°，换算成编码器计数只有
> **0.3125 个**，小于伺服的到位容差 `STEP_MOTOR_POSITION_TOLERANCE_COUNTS`（1）——
> 那样的目标伺服直接判为已到位，**一个脉冲都不会发**。
>
> 也就是说，**闭环下的「最小可指令位移」由到位容差决定，不由细分数决定**。容差能压到
> 多小见「精细度的三道闸」一节。细档按容差派生的好处是：以后改容差它自动跟着变，
> 不会悄悄失效。

点动以**目标**为基准累加，不是以实测位置：连点时上一步往往还没走完，按实测算会把没走
完的那段吃掉，点 n 次走不满 n 步。**因此位置不会累积误差**——目标每次精确加一个步长，
单次落点的 ±容差 不确定度不会传到下一步。目标被软限位夹掉时动作栏显示 `CLAMPED`，
第四行常驻显示 `LIMIT max` / `LIMIT min`——`JOG` 点不动最常见的原因就是顶到了边界。

长按调档**到头不回绕**：回绕的话一按过头就从最细跳到最粗，下一次点动会把摆杆甩出去
一大截。双击也认（走 2 步），因为按键驱动的短按要等过双击窗口
（`KEY_DOUBLE_CLICK_MS`，300ms）才上报，手快连点两下只会得到一个双击事件。

### 精细度：两件独立的事

「精细度」在这套驱动里指两件互不相干的事，调法完全不同，先分清再动手：

| | 步进精细度 | 定位精细度 |
|---|---|---|
| 定义 | 一个微步走多远 | 伺服停下时离目标多远 |
| 决定它的 | `STEP_ANGLE_DEG / MICROSTEP` | `POSITION_TOLERANCE_COUNTS` |
| 当前值 | **0.05625°** = 0.3125 计数（×32） | **±0.18°** = 1 计数 |
| 怎么改 | **驱动器拨码**，固件只能跟随 | 改宏，纯软件 |
| 影响什么 | 运动平顺度、共振、低速能不能匀速 | 落点准不准、控制环在目标附近的死区 |

按从粗到细排，三道闸是：

| 闸 | 值（电机轴） | 计数 | 能不能改 |
|---|---|---|---|
| 到位容差 `POSITION_TOLERANCE_COUNTS` | 0.18° | 1 | ✅ 纯软件，**已压到底** |
| 编码器量化 `360 / ENCODER_COUNTS_PER_REV` | 0.18° | 1 | ❌ 硬件 |
| 一个微步 `STEP_ANGLE_DEG / MICROSTEP` | 0.05625° | 0.3125 | 驱动器拨码 |

×32 之后**执行远细于反馈**（0.3125 < 1 计数，约 3 个微步才动一个计数）——这是想要的
方向，代价是编码器分辨不出单个微步，靠计数验细分的 `TURN`（#2）从此失效，
细分只能以拨码为准。

- **定位精细度已经压到编码器的物理地板，不是细分的问题。** 容差 = 1 计数 = 编码器分辨
  一次位置变化所需的最小量，再往下就没有可比较的量了（误差是整数计数，容差 0 意味着
  只接受精确相等）。所以提高细分**不会**让定位更准。
  容差能取到 1，是 ×32 换来的：容差的下限由**微步粒度**卡着——电机只能停在微步位上，
  ×32 时每微步 0.3125 计数，任何整数计数目标附近总有微步位可落（最远差 0.156 计数）；
  ×8 时代每微步 1.25 计数，那时取 1 是够不着的。
  编码器量化（±0.5 计数）已按明确要求不作为约束考虑——它是这条链上唯一还没被排除的
  物理因素，真机上若出现「停不下来、持续小幅补偿」，嫌疑就在它，把容差抬回 2 即可。
- **步进精细度的瓶颈是拨码档位与步进频率预算。** 同转速下细分翻倍，脉冲率就翻倍：

  | 细分 | 每微步（轴） | 每微步（计数） | 240 deg/s 所需 `f` | 5000 Hz 对应顶速 |
  |---|---|---|---|---|
  | ×8 | 0.225° | 1.25 | 1067 Hz | 1125 deg/s |
  | ×16 | 0.1125° | 0.625 | 2133 Hz | 562 deg/s |
  | **×32（当前）** | **0.05625°** | **0.3125** | **4267 Hz** | **281 deg/s** |
  | ×64 | 0.028° | 0.156 | 8533 Hz | 140 deg/s ← 会被钳 |

  超过 `MAX_STEP_FREQ_HZ`（5000）会被**静默钳位**、不报错。×32 下顶速 281 deg/s 仍高于
  `MAX_SPEED_DEG_S`（240），所以当前不会被钳；但**再提转速上限就会**，而且这个 5000
  至今是占位默认值、没实测（#7）——×32 让它第一次成为真约束。
- **编码器倍频改不了。** MSPM0 的 TIMG QEI 只有 2-input / 3-input 两种模式
  （`DL_TIMER_QEI_MODE`），没有倍频档位，每转计数由编码器线数定死。要更细只能换更高
  线数的编码器，或把编码器挪到减速后的输出轴上。
- **摆杆角的分辨率还要再除以减速比 `k`**（#9）。要提高摆杆端的精细度，加大减速比比
  在固件里做任何事都有效。

> ⚠ 改细分**必须先拨拨码，再改 `STEP_MOTOR_MICROSTEP`**，两边不一致不会报任何错，
> 只会让转速整体差一个固定倍数——宏填大一倍就多发一倍脉冲，限速、上电抬升速度、
> 越界纠正速度全部跟着翻倍。
>
> 细分提高后步进频率整体上移，`SWEEP`（#7）**必须重跑**：×32 下顶档 240 deg/s 就是
> 4267 Hz，已经贴着未实测的 5000。好消息是微步越细越容易跟得上，实测失步频率通常比
> ×8 时更高；坏消息是单微步转矩更小，极低速下可能"该走不走"（闭环会补，表现为轻微顿挫）。
>
> 另外 62500 Hz 的定时器时钟在高频端量化变粗：4267 Hz 时装载值 14.65 → 15，实际频率
> 4167 Hz，转速偏 −2.3%。闭环会吸收掉，不必处理；真要治就降 SysConfig 的分频、抬高
> `STEP_TIMER_CLK_HZ`，代价是 16 位装载值决定的最低频率跟着抬高。
>
> 脉冲宽度不用担心：4267 Hz 时高电平 7/62500 = 112 µs，远超驱动器要求的 µs 级下限。

#### 回差带：让"停得准"不再以"抖"为代价

单阈值下收紧容差会引出末端抖动：摆杆带重力负载，停脉冲后靠保持力矩顶着会下沉一点，
下沉两三个计数就触发补偿，补完又沉，形成极限环。所以到位判定改成**两个阈值**：

```
未到位 ──|误差| ≤ POSITION_TOLERANCE_COUNTS (1)──► 到位（停脉冲）
到位   ──|误差| > SERVO_RESUME_COUNTS      (6)──► 未到位（重新出脉冲）
```

「停多准」由容差决定、「漂多少才重新动」由 `SERVO_RESUME_COUNTS` 决定，两件事解耦。
`RESUME` 取 6 略宽于最初的容差 5，所以**抗漂移能力不比动手之前差，停得却准了 5 倍**。
容差从 5 一路收到 1 时 `RESUME` 刻意不跟着收——它挡的是机械下沉，与定位精度无关。

`StepMotor_IsAtTarget()` 直接返回这个状态，不另算一遍——回差带下"另算一遍"必然和伺服的
判断不一致。**新目标一下发就清掉到位状态**，回差只在停住不动时挡漂移，不会吃掉点动
指令（否则小于 `RESUME` 的点动会被当成漂移忽略）。

> ⚠ 这一组是**上板必验项**：进 `JOG` 走到中段，松手静置十几秒，看 `cnt` 是否稳定、
> 电机是否反复"咔咔"补偿。
>
> - **静置时反复补偿** → `SERVO_RESUME_COUNTS` 偏小，往上加（先试 8、10）。
>   若连 `RESUME` 加大都压不住，说明保持力矩不够顶住摆杆自重，那是驱动器电流或机械的
>   问题，不是这两个宏能解决的。
> - **点一下之后停不下来、持续小幅爬行** → 容差 1 太紧，编码器量化噪声让它进不了带内。
>   抬回 2。这是容差取 1 唯一没被排除的风险（量化噪声按明确要求未作为约束考虑）。

编码器计数**全程不清零**——它是 #11 编码器限位赖以判定的坐标系，清零一次限位就护在
错的地方了。需要"从零起测"的模式（`TURN`/`HAND`/`SWEEP`）改为记下进入时的计数，
屏上 `rel` 行显示差值，坐标系和限位保护因此不受影响。
页内暂停一律保留读数——停下来正是为了读它。

`[SM]` 遥测每行的字段：`m` 模式序号、`t` 时间戳、`cnt` 编码器累计计数、
`tgt` 目标计数、**`err` 位置误差（丢步的直接指标）**、`deg` cnt 换算的电机轴角、
`cmd` 伺服本拍下发的速度（只读，不是指令）、`f` 实际步进频率、`en` 使能状态、
`g` 守护状态。进入页面时另打一行 `clk / min_f / max_f / ustep / cpr`，
便于与驱动器拨码、SysConfig 分频当场对账。

## 1. 定时器时钟 —— 核对，不是测量

驱动用 `period = CLK / f` 算装载值，这个数错了**所有**转速都按同一比例偏。

打开 `board/sys_config/ti_msp_dl_config.h`，确认 `SMotor_INST_CLK_FREQ` 等于 `62500`
（32 MHz ÷ clockDivider 8 ÷ clockPrescale 64）。没动过 SysConfig 分频就跳过。

**改过分频就必须同步 `step_motor.h`**——编译器不会报错，只会静默变速。

> **#2 量的其实是本值与 `MICROSTEP` 的比值。** 推导里两者只以比值出现，任一个错了另一个
> 都会补偿回来，角度刻度照样准——单靠数转过几圈分不出是谁错。判别办法是拿拟合出的
> `MICROSTEP` 去对驱动板拨码开关：**对得上**说明本值没被用来吸收误差，时钟正确；
> **对不上**（比如拟合 8 而拨码 32）说明真实时钟是 `62500 × 32/8 = 250 kHz`，
> 所有频率量的含义都差 4 倍，得回 SysConfig 查分频。
>
> 本机已核对：拟合 8、拨码 8，一致，62500 Hz 正确。

## 2. 细分数 `MICROSTEP` —— `TURN` 模式

先读驱动板拨码开关的细分表填进去，然后实测复核。

0. 先读驱动板拨码开关，记下它标称的细分数——第 4 步之后要拿来对账。
1. 轴上贴个标记，切到 `TURN`（进入即自动记基准）。
2. UP/DOWN 设 `N`（默认 1 圈；不确定时设 2，判读更准）。
3. ENTER 开始。驱动走满 `N × 360°` **自动停**，状态显示 `DONE`。
4. 看标记实际转过几圈。

```
MICROSTEP_正确 = MICROSTEP_当前 / 实际圈数 × N
```

实测记录：`N=1`、填的 32、实际转了 4 圈 → 真实细分 `32/4 = 8`，与当时的拨码读数一致。
**现已把拨码拨到 ×32、宏改为 `32.0f`**（为提高步进精细度，见「精细度：两件独立的事」）。
换驱动板或拨过拨码后必须重做本项。

> **这一项光看遥测标不出来。** 下发的脉冲频率是用同一个 `MICROSTEP` 算的，永远自洽。
> 必须靠眼睛数实际圈数。
>
> ⚠ **装机后本项基本做不了**：走 N 圈的目标会被限位夹住（页面 l4 显示 `CLAMPED`）。
>   而且 ×32 下一个微步（0.3125 计数）远细于一个编码器计数，`c/N` 那条交叉验证也不再
>   有分辨力。装机后细分**只能以拨码为准**——两边不一致不报错，只让转速整体差固定倍数。
>
> 装机后想复核宏与拨码是否一致，实际可行的办法是**量转速**：`JOG` 粗档（75 计数）点一下
> 计时，或 `SWEEP` 低档下看 `cnt` 的斜率，与设的速度上限对比。宏比拨码大一倍就快一倍。

页面上的 `c/N` 栏是 `rel / N`，即编码器每转计数的交叉验证值——等 #5 做完回来再看，
两者对不上说明 #2 或 #5 至少有一个还是错的。

## 3. 使能极性 `ENABLE_HIGH` —— `HAND` 模式

`HAND` 与 `SPAN` 进入时自动断电、离开时自动恢复，正好用来验证 EN 线是否真的起作用：

- 在 `RUN` 模式拧电机轴：应该**拧不动**（有保持力矩）。
- ENTER 长按切到 `HAND`：应该**能自由拧动**，第一行显示 `drv OFF turnable`。

两种状态表现一样，说明 EN 线没接通、或驱动器 EN 脚悬空默认使能；表现相反（`RUN` 能拧、
`HAND` 拧不动），把 `STEP_MOTOR_BEAM_ENABLE_HIGH` 改成 `0U`。

若切到 `HAND` 后第一行显示 `!! still ON !!`，是驱动层没能真正断电，先查这个再往下做。

实测记录：高电平使能，`1U` 正确。

## 4. 方向极性 `POSITIVE_DIR_HIGH` —— `RUN` 模式

先在机械上定死哪边是正方向（比如"抬右侧"），约定**正速度 = 摆杆向正方向偏**。

`RUN` 模式按 UP（正速度）观察摆杆倒向：一致则现值正确，相反则把
`STEP_MOTOR_BEAM_POSITIVE_DIR_HIGH` 从 `1U` 改成 `0U`。

⚠ 这一项和 #6 必须**分开做、按顺序做**。两个一起翻会互相抵消，测出来的组合是错的但
现象是对的。

实测记录：DIR 高电平即正向，`1U` 正确（`ENCODER_INVERT` 已单独定为 `1U`，两者不是
一起翻的）。

## 5. 编码器每转计数 `ENCODER_COUNTS_PER_REV` —— `HAND` 模式

这是唯一必须实测、猜不出来的值。它错了，`deg` 那一栏的刻度就是错的，闭环也就无从谈起。

1. ENTER 长按切到 `HAND`（自动断电）。
2. ENTER 重设基准（rel 行归零；编码器本身不清，限位坐标系要保住）。
3. 手动把轴**正好转 N 整圈**（对准标记慢慢转，别来回找）。转 3~5 圈能摊掉对不准的误差。
4. UP/DOWN 把 `turns` 设成你实际转过的圈数。
5. 读 **`cpr` 栏** —— 那就是 `STEP_MOTOR_ENCODER_COUNTS_PER_REV`。

改完重新烧录，回 `HAND` 再转一圈验证：`cpr` 应该稳定在同一个数，`RUN` 里的 `deg` 转
一圈应读到接近 `360`。

实测记录：断电手转一整圈，`cnt` 变化 **2000**，已填 `2000.0f`。

> MSPM0 的 QEI 2-input 模式对 A/B 各取上升沿，是 **2 倍频**，不是常见的 4 倍频，
> 所以理论值 = 编码器线数 × 2。2000 / 2 = **1000 线**，是常见规格，与原先按 500 线
> 猜的默认值差一倍。测出来接近线数 × 4，说明 SysConfig 的 QEI 模式和驱动里的注释
> 对不上，得回去查。

## 6. 编码器方向 `ENCODER_INVERT` —— `RUN` 模式

#4 和 #5 都定完之后，`RUN` 模式按 **UP**（正方向）跑两秒：

- `cnt` **增大** → 方向一致，保持现值。
- `cnt` **减小** → 方向相反，翻转 `STEP_MOTOR_ENCODER_INVERT`。

判据就这么直接：驱动内部所有方向（限位、纠正、抬升）都以"计数增大 = 电机正方向"
为约定，这一条不成立，后面每一项都是反的。

实测记录：翻转前电机正转时 `cnt` 反而减小，故取 `1U`。

改完再跑一次，`err` 栏应在跟踪误差附近小幅波动而不持续增大——持续增大就是丢步，
直接进 #7。

## 7. 最大步进频率 `MAX_STEP_FREQ_HZ` —— `SWEEP` 模式

`5000` 是抄官方例程的，与本机电压、负载、摆杆惯量都无关，必须自己压出来。

1. 切到 `SWEEP`，UP/DOWN 选转速档（`15 / 30 / 60 / … / 240` deg/s）——设的是伺服
   **速度上限**，目标在远处，所以整段都跑在这个速度上。
2. ENTER 启动，摆杆在软限位内往复跑，看 **`peak` 栏**（本档 `|err|` 的峰值，
   单位是编码器计数）。
3. ENTER 停止，UP 升一档，再来。换档会自动清零峰值并重新计数。

判据：不丢步时 `err` 稳定在**跟踪误差**附近——那是比例律的固有稳态偏差，
约 `速度 ÷ SERVO_KP` 换算成的计数（例如 60 deg/s ÷ 3.0 = 20deg ≈ 111 计数）。
`peak` 明显跳出这个量级、或听到"咔咔"堵转声 → **已经丢步**，退回上一档。

取**能稳定跑的最高档的 80%** 作为工作上限（给摆杆动态加速留余量），`f` 栏就是该转速
换算出的步进频率，直接抄回 `STEP_MOTOR_MAX_STEP_FREQ_HZ`。

⚠ 必须**装上摆杆、带真实负载**测。空载能跑到的频率，挂上摆杆通常要打对折。

> 用峰值而不是瞬时值：丢步是突发的，盯瞬时数容易在两次刷屏之间漏掉。
> 往复运动的换向瞬间 `err` 会短暂跳高，那是正常的，看的是稳态段的峰值水平。

## 8. `MAX_SPEED_DEG_S` —— 换算

不单独测，由 #7 反推，两者保持一致：

```
MAX_SPEED_DEG_S = MAX_STEP_FREQ_HZ × STEP_ANGLE_DEG / MICROSTEP
```

不一致的后果是限幅在两处各切一刀，实际上限取更严的那个——不会出错，但会让调参时
"改了没反应"。

## 9. 摆杆减速比 `k` —— `SPAN` 模式

驱动层的所有角度都是**电机轴角**，不是摆杆角。中间隔着连杆 / 同步带 / 减速箱：

```
摆杆角 θ = 电机轴角 / k
```

1. 切到 `SPAN`。**用手**把摆杆推到一个明确的机械参考位
   （比如靠住限位块）。
2. ENTER 打 **A** 点。
3. 推到另一个参考位，ENTER 打 **B** 点。
4. 读 **`d` 栏** —— 两点间的电机轴角（deg）。`A`/`B` 两栏显示的是**原始计数**，
   那是 #11 要的数；`d` 才是角度。
5. 用量角器或手机水平仪量摆杆实际转过的角度 `θ`。

```
k = d / θ
```

同步带直连的话 `k` 就是带轮齿数比，有减速箱要再乘减速比——量出来的值应该和机械算出来
的对得上，对不上说明中间有打滑或 #5 还没标准。

> `A`/`B`/`d` 都由编码器计数换算而来，所以 **#5 必须先做完**，否则这三个数的刻度是错的。

## 10. ~~开环软限位与 `est` 估计~~ —— 已删除

原先有两样东西已随驱动精简一并删除：

- **开环软限位**（`MIN/MAX_POSITION_DEG` + `SetPositionLimit()`）：阈值一直放在
  ±100000 等效关闭，职责又与 #11 的编码器限位完全重复，是纯死代码。
- **开环估计位置 `est`**（速度积分）及由它派生的 `slip = est - qei`：它是开环时代的
  遗留。闭环之后**位置误差 `err` 本身就是更直接的丢步指标**——不丢步时 `err` 稳定在
  跟踪误差附近，丢步时电机没走到、编码器落后，`err` 会超出该值且不收敛。
  #6 和 #7 的判据都已改用 `err`。

## 11. 编码器限位与上电抬升 —— 写宏，无标定页

这是摆杆装机后**真正生效**的那套行程保护，判的是 QEI 实测计数，丢步、手推、机械打滑
都看得见。没有现场标定程序：量一次、把数写进 `step_motor.h`、重编译。

### 坐标系约定（先读这一条）

固件没有绝对位置传感器。`StepMotor_Init()` 把编码器计数**清零**，所以

```
计数零点 = 上电时刻摆杆所在的物理位置
```

下面所有计数常数都相对这个零点。因此必须有一条上电约定，推荐用**断电自重靠住的那一端**
作参考位——上电前驱动器本来就没通电，摆杆自然落到那里，不用人去摆，重复性还比人眼
对水平好。

于是坐标系长这样（假设摆杆落向负方向端）：

```
        0        20              154              430      450
        │         │               │                │        │
        ├─MARGIN──┤               │                ├─MARGIN─┤
        │         │               │                │        │
    HARD_MIN  SOFT_MIN          水平位          SOFT_MAX  HARD_MAX
   上电参考位                   抬升目标                另一端机械端
   （自重靠住）
```

（图中的数值是本机实测填入的当前值：行程 450 计数、余量 20、水平位 154。）

> ⚠ **上电瞬间摆杆就在软限位之外**（0 落在 `SOFT_MIN` 外侧）。这是正常的：上电抬升
> 把它送进合法区之后限位才真正开始工作。抬升失败时守护会一直报 `GUARD_STALLED`，
> 那是在如实反映「摆杆还瘫在端点上」。

若机械上有配重、断电不会靠向固定一端，那就得改约定为**上电前人工摆到某个固定位**。
驱动**不提供**平移坐标系的接口（`SetEncoderCount` 一类）——零点只在 `Init` 建立一次，
平移一次限位边界就全失去意义了。

### 限位宏

| 宏 | 含义 |
|---|---|
| `STEP_MOTOR_ENC_LIMIT_ENABLED` | 上电是否启用。**数填对之前保持 0** |
| `STEP_MOTOR_ENC_HARD_MIN/MAX_COUNTS` | 两端机械极限，只作记录不直接生效 |
| `STEP_MOTOR_ENC_LIMIT_MARGIN_COUNTS` | 向内收的安全余量，**由你选** |
| `STEP_MOTOR_ENC_SOFT_MIN/MAX_COUNTS` | 唯一生效的边界，默认 `HARD ∓ MARGIN`；要直接指定就改成裸常数 |
| `STEP_MOTOR_ENC_LEVEL_COUNTS` | 水平位计数，即抬升行程；同时是摆杆角参考零点 |

### 怎么量 `HARD_MIN/MAX` 与 `LEVEL`

用 `Device Check -> Step Motor` 的 `SPAN` 模式——它进入时自动**断电**，靠手推取数，
且不清零编码器，坐标系正是所需的：

1. 上电（摆杆自重靠住），进 `SPAN`。此时 `cnt` 行显示 0 附近。
2. **用手**把摆杆推到一端机械极限，`ENTER` 打 **A**。
3. 推到另一端，`ENTER` 打 **B**。
4. `A` / `B` 两行显示的就是 **原始计数**，直接抄进 `ENC_HARD_MIN/MAX_COUNTS`（小的填
   MIN）。`d` 行仍是角度，那是给减速比 `k`（#9）用的。
5. 把摆杆推到水管**大致水平**处，读 `cnt` 行，抄进 `ENC_LEVEL_COUNTS`。

`LEVEL` 要量得准就改用 `JOG`：`HARD_MIN/MAX` 与 `MARGIN` 填好、重新烧录之后，进
`JOG`（进页默认就是它），中档粗调、细档微调，把水管调到水平，读 `cnt` 行抄进
`ENC_LEVEL_COUNTS`。比 `SPAN` 手推准得多——手一松摆杆就会往下掉一点，`JOG` 是电机
带着保持力矩顶住的。改完重新烧录，上电抬升就会停在这个位置。

也可以纯换算：`计数 = 摆杆角 × k × ENCODER_COUNTS_PER_REV / 360`。

`MARGIN` 要覆盖「判越界到真正停住」多走的距离：`Tick 周期 × 转速` + 负载惯量过冲
+ 机械公差。第一项可算：满速 240 deg/s = 1333 counts/s，10ms 周期 → 13 counts。

### 上电自动抬升

上电后摆杆自重靠在一端、水管是歪的，控制器接管前得先抬到工作位。这一段由
`StepMotor_Tick()` 里的状态机非阻塞跑完：

```
上电 → Init 清零编码器 → 等 DELAY_MS → 使能驱动器
     → 以 LIFT_SPEED 朝 LIFT_TARGET 走 → 到位停住（按 HOLD 决定是否保持通电）
```

| 宏 | 默认 | 说明 |
|---|---|---|
| `STARTUP_LIFT_ENABLED` | `1U` | 关掉则上电一直失能，摆杆保持自重姿态 |
| `STARTUP_LIFT_TARGET_COUNTS` | `ENC_LEVEL_COUNTS` | 抬升目标，下发前先按 HARD 再按 SOFT 夹两道 |
| `STARTUP_LIFT_SPEED_DEG_S` | `45.0f` | 带重力负载起步，快了丢步 |
| `STARTUP_LIFT_TOLERANCE_COUNTS` | `10` | 到位容差，太紧会在目标附近来回修 |
| `STARTUP_LIFT_DELAY_MS` | `800U` | 上电到开走的等待，机器不该一通电就自己动 |
| `STARTUP_LIFT_TIMEOUT_MS` | `8000U` | 超时未到位 → 停机失能进 `STARTUP_FAULT` |
| `STARTUP_LIFT_HOLD` | `1U` | 到位后保持使能，否则立刻掉回去 |

抬升期间**独占目标**：`StepMotor_MoveToCount()` 返回 `BSP_STATUS_BUSY` 并被忽略。
上层据此得知抬升尚未结束，也可调 `StepMotor_AbortStartup()`
主动放弃（`Device Check -> Step Motor` 页进入时就是这么做的）。`StepMotor_Stop()` 始终
有效。

抬升优先于限位判定：目标已事先夹进软限位，抬升未结束前不做越界纠正，免得两个自动动作
互相拉扯；超时是它的兜底。

### 运行期限位行为

- `StepMotor_Tick()` 由调度器每 `STEP_MOTOR_TICK_PERIOD_MS`（10ms）调用，与应用
  状态无关——菜单里、任务里、故障态下限位都在。改大这个周期必须同步加大 `MARGIN`。
- 越界时先停脉冲，再以 `GUARD_RECOVER_SPEED_DEG_S` 反向把摆杆挪回「限位再向内
  `RECOVER_HYST_COUNTS`」处。纠正期间同样返回 `BSP_STATUS_BUSY`。
- 纠正超过 `GUARD_RECOVER_TIMEOUT_MS` 仍没回来 → 停机失能进 `GUARD_FAULT`。多半是
  编码器断线、机械卡死或方向极性反了，查清楚后重新上电（驱动不提供运行期清除接口）。
- 驱动器失能时越界只报 `GUARD_STALLED`，**不自动上电**——手推着量行程时不该被电机抢走。
- 目标在 `StepMotor_MoveToCount()` 里就被夹进合法范围，**限幅只有这一个入口**，
  上层不需要（也没有接口）自己夹一遍。守护是兜底，正常路径不该走到它。

> ⚠ 限位**全程有效，没有运行期开关**。`Device Check -> Step Motor` 页也不例外：
> 它从头到尾不清零编码器（只记基准值），所以坐标系一直有效、保护一直都在。
>
> 要越过软限位量机械行程，用 `HAND` / `SPAN` 的**断电手推**——这两个模式进入时自动
> 失能驱动器，伺服不出力、守护也无从纠正，编码器却照常计数。这比"临时关限位"安全，
> 也不会留下忘了开回来的隐患。
>
> 代价是 `TURN` 在装机后基本做不了：走 N 圈的目标会被限位夹住（页面 l4 显示
> `CLAMPED by limit`）。细分数本来就该在装摆杆之前标，真要重标得先拆下摆杆，
> 或临时把 `STEP_MOTOR_ENC_LIMIT_ENABLED` 设 0 重编译。
>
> ⚠ 软限位防的是控制器和操作者的失误，**不能替代物理限位开关**。

## 常见现象对照

| 现象 | 可能原因 |
|---|---|
| 只嗡嗡响不转 | 驱动板线序错（A+/A-/B+/B- 接反），或 `f` 超出电机启动频率 |
| 电机在转、`cnt` 不动 | 编码器供电 / A、B 线未接，或 QEI 引脚接错 |
| 按 UP 时 `cnt` 反而减小 | `ENCODER_INVERT` 需翻转（#6） |
| `err` 越跑越大 | 丢步，降 `MAX_STEP_FREQ_HZ`（#7）或加大驱动电流 |
| 转速整体差固定倍数 | `MICROSTEP`（#2）或 `STEP_TIMER_CLK_HZ`（#1）不对 |
| `f=0` | 伺服算出的速度落进死区，低于 `MIN_STEP_FREQ_HZ` |
| `HAND` 页显示 `!! still ON !!` | EN 极性错或 EN 线未接（#3） |
| `JOG` 点一下没反应，第四行 `LIMIT max/min` | 目标顶在软限位上，往回点 |
| `JOG` 单击要等一下才动 | 正常：短按要等过双击窗口（300ms）才上报 |
| `JOG` 手快连点两下只走了 2 步而非 4 步 | 正常：连点被识别成双击，双击定义为 2 步 |
| `TURN` 走完圈数明显不对 | `MICROSTEP` 不对（#2），这正是该模式要测的 |
| 上电静默约 0.8s 后摆杆自己抬起 | 正常，上电自动抬升（#11），由 `STARTUP_LIFT_DELAY_MS` 决定静默时长 |
| 上电电机不响也不锁轴 | `STARTUP_LIFT_ENABLED=0`，或抬升已完成且 `HOLD=0` |
| 上电摆杆朝**反方向**顶 | `POSITIVE_DIR_HIGH`（#4）或 `ENCODER_INVERT`（#6）反了；抬升会超时进 `STARTUP_FAULT` |
| 抬升走到一半停住、失能 | 抬升超时（#11）：`LIFT_TIMEOUT_MS` 太短、丢步、或目标计数填错 |
| 摆杆自己往回挪一段然后停 | 编码器限位在纠正越界（#11） |
| `MoveTo` 返回 `BUSY`、指令没反应 | 上电抬升还没结束，等它抬完或调 `StepMotor_AbortStartup()` |
| 下了 `MoveTo` 但电机纹丝不动 | `StepMotor_Tick()` 没被周期调用——伺服不跑，脉冲就不会出 |
| 复能后要动，第一条指令"丢了" | 正常：失能→使能会把目标同步到当前位置，须重新下位置指令 |
| 到位后在目标附近来回抖 | `SERVO_RESUME_COUNTS` 偏小（先加大它），或 `SERVO_KP` 偏大 |
| 点动一下电机没反应、`err` 却不为 0 | 位移小于到位容差，伺服判为已到位；步长要 > `POSITION_TOLERANCE_COUNTS` |
| **换向后第一下按键电机不动**，同方向连点正常 | 步长 ≤ `2 × 容差`：残余误差与行进方向同号，换向后被抵掉。步长须 > `2 × 容差` |
