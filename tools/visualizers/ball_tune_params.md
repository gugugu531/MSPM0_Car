# 滚球控制可调参数说明

配合 `ball_tune.html` 使用。参数表定义在 `app/app_ball_scurve_task.c` 的
`H3S_TUNE_TABLE[]`，本文按同样顺序编排，**改固件表时请同步改本文**。

---

## 一、先读这段：热更能改什么、不能改什么

热更**只改内存，不写 flash**。掉电即恢复源码里的编译期默认值。

> 整定出来的数必须回填 `app_ball_scurve_task.c` 的 `H3S_SCURVE_CONFIG` 并提交，
> 才算数。整定台的「导出为 C」按钮就是为这一步准备的。

越界一律**拒绝并回报**，不做静默钳位——静默钳位会让人以为设进去了。

### ⚠ 参数的生效时机不一样

这是最容易踩的坑。13 个参数分两类：

| 类别 | 参数 | 何时读取 | 改完什么时候见效 |
|---|---|---|---|
| **每拍读** | kp / kd / fblim / dith_* / roll_* / lvl_bias | 控制回调每 20 ms | **下一拍立即** |
| **规划时读** | `amax` / `vmax` | 只在 `BallScurve_PlanTo()` 里 | **下一次规划才生效** |

后果：

- **Hold 模式下改 `amax`/`vmax` 完全没有效果**。Hold 模式跳过剖面规划
  （`profile_active = false`），根本不会调用 `PlanTo`，改了也读不到。
- SCurve 模式下改这两项，要等**下一个航点**才生效，当前正在走的这段剖面
  已经把系数解算完了，不会中途变。

想立刻看到 `amax`/`vmax` 的效果，就退出任务重进（Enter 会重新规划）。

## 二、参数详解

### 2.1 反馈增益（3 项）

控制律是绕**剖面参考点**的 PD（注意不是绕目标点）：

```
feedback_deg = kp × (x_ref − x) + kd × (v_ref − v)
```

剖面走完后 `x_ref` 钉在目标点、`v_ref = 0`，此时退化为绕目标的纯 PD。

#### `kp` — 位置增益

| | |
|---|---|
| 单位 | deg/mm |
| 范围 | 0.010 … 0.150 |
| 默认 | **0.04711** |
| 生效 | 每拍 |

球偏离参考点 1 mm，水管就多倾斜 0.04711°。

**默认值怎么来的**：取 ωn = 2.4 rad/s、ζ = 0.9，则 `kp = ωn²/K_G`，其中
K_G = (5/7)g = 7004.75 mm/s²/rad，再从 rad/m 换成 deg/mm。

**上下界的物理依据**：

- 下界 0.010：静摩擦残差有个与整定无关的数学下限 `θ_stick/kp`。实测
  θ_stick ≈ 0.62°，kp = 0.010 时残差就是 62 mm，已经毫无意义。
- 上界 0.150：再高环路裕度不够，会震荡。

**调大**：响应快、静摩擦残差小；但超调和震荡风险上升。
**调小**：平稳；但残差变大——**方向和你想要的正好相反**，别为了「稳」而降 kp。

#### `kd` — 速度增益

| | |
|---|---|
| 单位 | deg/(mm/s) |
| 范围 | 0.005 … 0.100 |
| 默认 | **0.03533** |
| 生效 | 每拍 |

阻尼项。由 `kd = 2ζωn/K_G` 推出（同上 ωn/ζ）。

**调大**：抑制超调和震荡；但过大会让响应迟滞，而且 `kd × v` 在巡航速度下
容易顶穿 `fblim`（见下）。
**调小**：响应快；但欠阻尼会震荡。

> **饱和陷阱**：曾实测到 6.42 rad/s 的极限环，成因是 `kd × v = 0.03533 × 40
> = 1.41°`，而 `kp × e` 只有 0.57°，两者合计顶穿 ±2° 的 `fblim`。限幅一旦触发，
> 环路等效增益骤降，就震起来了。遥测里 `fbc` 位就是看这个的。

#### `fblim` — 反馈限幅

| | |
|---|---|
| 单位 | deg |
| 范围 | 1.0 … 5.0 |
| 默认 | **2.0** |
| 生效 | 每拍 |

对 `kp·e + kd·ė` 之和的对称限幅，**不含前馈**。前馈另算，两者相加后还要过
一道物理限幅 −5.2°…+5.1°。

上界 5.0 的依据：查表在软限位 20…430 cnt 上的角度范围是 −5.345°…+5.236°，
留 0.1° 余量。设到 5.0 时反馈自己就能吃掉全部权限，前馈会被挤掉。

**调大**：抗扰权限大、不易饱和；但一次视觉野值就能让水管猛甩。
**调小**：温和；但容易饱和，饱和后环路特性突变（见上面的饱和陷阱）。

### 抖动 — 破静摩擦

先说清楚**为什么需要它**。

球停住的条件是 `|净倾角| < 脱离角`。此时控制器再怎么加大倾角也推不动，
因为它已经在死区里。纯 PD 的稳态残差因此有一个**与整定无关的数学下限**：

```
残差 = θ_stick / kp
```

2026-07-31 实测（COM16，75 s 无扰动）：球停在 −36.9 mm、目标 −50 mm，控制器
持续输出 −0.620° 而球一动不动 ⇒ **θ_stick ≈ 0.62°**。代入 kp = 0.04711 得
下限 **13.2 mm**，与实测 13.1 mm 完全吻合。

也就是说：**不破静摩擦，±10 mm 判据在这台机器上数学上不可达。**抖动是目前
唯一的突破机制。

原理：注入 `A·sin(2πft)`，让净倾角周期性越过脱离角，球一小段一小段挪动；
误差进入 `dith_minerr` 后自动停振，让静摩擦把球锁在那里。破摩擦让它爬过去，
停振让它留下来。

> ### ⚠ 默认参数下抖动是无效的
>
> 指令角要经过步进位置环才变成真实水管角，而位置环是一阶滞后，时间常数
> `τ = 1/SERVO_KP`。本基线 `SERVO_KP = 3.0` ⇒ **τ = 0.333 s**，
> 对 f 的衰减为 `1/√(1+(2πfτ)²)`：
>
> | f (Hz) | 衰减 | 0.97° 指令 → 管身 | 破 0.62° 所需指令 | 球纹波 |
> |---|---|---|---|---|
> | 0.5 | 0.691 | 0.670° ✓ | 0.90° | 7.7 mm |
> | **1.0** | 0.431 | 0.418° ✗ | **1.44°** | **1.9 mm** |
> | 1.5 | 0.303 | 0.294° ✗ | 2.04° ✗ 越界 | 0.85 mm |
> | **2.0（默认）** | 0.232 | **0.225° ✗** | 2.67° ✗ 越界 | 0.48 mm |
>
> **默认 0.97° @ 2 Hz 只能让管身抖 ±0.225°，而破静摩擦需要 0.62°，缺口 64%。**
> 而且 2 Hz 下所需的 2.67° 已超出 `dith_amp` 上界 2.0——**在 2 Hz 上无解**。
>
> 源码注释里写的「衰减 0.62 倍、管身抖 ±0.6°」是按 `SERVO_KP = 10`（τ = 0.1 s）
> 算的。那是之前用运行期接口临时提到 10 时的数，**后来回退了，注释没跟着改**。
>
> **可行组合**（球纹波 ∝ A/f²，所以低频要付纹波的代价）：
>
> - `dith_freq=1.0, dith_amp=1.44` — 管身 0.62°，纹波 1.9 mm ← **推荐**
> - `dith_freq=0.5, dith_amp=0.90` — 管身 0.62°，纹波 7.7 mm（吃掉大半预算）
>
> 这一条只有推导，**没有实机验证**。上板第一件事就是确认它。

#### `dith_amp` — 抖动幅值

**范围** `0 ~ 2.0` deg｜**默认** `0.97`｜**每拍生效**

指令角上叠加的正弦幅值。**0 = 完全关闭抖动**（此时落点残差回到 13.2 mm 下限）。

上界 2.0 由角速率约束推出：`2πf·A < angle_rate_limit`。f=2 Hz、A=2.0 时需
25 deg/s，而斜率限制是 240 deg/s，留有余量——所以真正的约束是上面那张衰减表。

调大 → 更容易破摩擦，但球的纹波按 `A/f²` 增大，吃掉 ±10 mm 预算。

#### `dith_freq` — 抖动频率

**范围** `0.5 ~ 5.0` Hz｜**默认** `2.0`｜**每拍生效**

**这是抖动里最反直觉的一项：调高频率会让抖动变弱，不是变强。**

因为位置环的衰减 `1/√(1+(2πfτ)²)` 随 f 单调下降。f 从 1 Hz 到 2 Hz，衰减从
0.431 掉到 0.232——几乎砍半。而破摩擦要求的是**管身实际幅值**，不是指令幅值。

代价方向相反：球纹波 ∝ `A/f²`，低频纹波大。所以要在「破得动」和「纹波小」
之间找平衡点，当前 τ 下这个点在 **1 Hz 附近**。

#### `dith_minerr` — 停振误差阈值

**范围** `0 ~ 20` mm｜**默认** `3.0`｜**每拍生效**

误差小于此值就停振。**这一项同时提供了「捕获」语义**：抖动让球爬过来，
停振让静摩擦把它锁在原地。设 0 = 永不停振，球会一直在目标附近颤动。

默认与 `settled_position_mm`（3 mm）对齐——进了稳定判据就该停。

#### `dith_maxspd` — 触发速度上限

**范围** `0 ~ 50` mm/s｜**默认** `8.0`｜**每拍生效**

球速高于此值不抖。**这一项是防止误判的**：球还在滚说明不是被钉住，此时抖动
只会干扰正常的 PD 收敛。设 0 = 不看球速（不建议）。

#### `dith_dwell` — 触发驻留

**范围** `0 ~ 5.0` s｜**默认** `0.5`｜**每拍生效**

「误差超阈 + 球不动」要连续满足多久才起振。防止在瞬态里误触发。

### 前馈与标定

#### `roll_ff` — 滚阻前馈

**范围** `-1.0 ~ +1.0` deg｜**默认** `0.0`｜**每拍生效**

按参考速度方向施加的固定倾角，补偿滚动阻力与管道坡度。正负号跟随 `v_ref`：

```c
rolling_ff_deg = (v_ref > 0) ? +roll_ff : -roll_ff;
```

**默认 0 是刻意的**——先跑一趟测出实际欠冲量 `d`，再按 `θ_roll = 2d/(K_G·T²)`
反解填回。拍脑袋填值会把一个可测量的系统性偏差换成一个不可测的。

#### `roll_db` — 滚阻前馈死区

**范围** `0 ~ 10` mm/s｜**默认** `3.0`｜**每拍生效**

`|v_ref|` 低于此值时不施加滚阻前馈。防止在剖面起止端（v_ref≈0）出现符号抖动。

#### `lvl_bias` — 动力学水平点偏置

**范围** `-2.0 ~ +2.0` deg｜**默认** `0.0`｜**每拍生效**

查表 0° 与**真实动力学水平点**的差值，直接加进指令角。

这一项最要命，因为它是**常值倾角误差**，在 T 秒的移动里造成
`0.5·K_G·Δθ·T²` 的落点偏差——Δθ=0.45°（15 cnt）、T=1.2 s 时就是 **40 mm**。

**默认 0 = 承认未标定。** 标定方法不需要额外动作，一趟正常移动就是辨识实验：
对遥测的 `(beam, aest)` 做线性回归 `aest = K·(beam − θ₀)`，零交点 `θ₀` 即真值。
`ball_scurve_monitor.html` 已内置这个回归（1 cnt ≈ 0.03°）。

### 轨迹限制

> ⚠ **这两项只在 `PlanTo` 时读取**，改完要重新规划才生效。详见下一节。

#### `amax` — 剖面峰值加速度

**范围** `50 ~ 500` mm/s²｜**默认** `200`｜**规划时生效**

五次剖面的峰值加速度上限，决定时长 `T_acc = √(5.7735·|Δx|/amax)`。

对应峰值倾角 `asin(amax/K_G)`：200 → 1.64°，500 → 4.1°。上界 500 是为了让
前馈角加上 `fblim` 后仍留在物理 ±5.2° 内。

#### `vmax` — 剖面峰值速度

**范围** `30 ~ 200` mm/s｜**默认** `90`｜**规划时生效**

峰值速度上限，决定时长 `T_vel = 1.875·|Δx|/vmax`。最终时长取两者较大值。

⚠ **与视觉链路耦合**：2026-07-31 实测树莓派在 40 mm/s 以上丢失率翻倍到
33~53‰（疑似运动模糊），而默认 90 正落在这个区间。视觉问题解决前，
调低 vmax 可能反而让整体表现更好。

## 生效时机：两类参数

这是**最容易踩的坑**。13 项参数分成两类，改完的效果完全不同：

| 类别 | 参数 | 生效时机 | 在 Hold 模式下 |
|---|---|---|---|
| **每拍读取** | 其余 11 项 | 下一控制拍（20 ms 内） | ✅ 立即生效 |
| **规划时读取** | `amax` `vmax` | 下一次 `PlanTo` | ❌ **永不生效** |

原因在代码里：`amax`/`vmax` 只被 `BallScurve_EstimateDuration()` 使用，
而它只在 `BallScurve_PlanTo()` 里调用一次，把结果冻结进多项式系数 `c[]`。
之后每拍的 `BallScurve_Evaluate()` 只读 `c[]`，不再看 config。

**后果**：

- **SCurve 模式**下改 `amax`，要等下一个航点（最多 2 s）才看到效果
- **Hold 模式**下改 `amax`/`vmax`，**完全没有任何效果**——Hold 模式从不规划剖面

所以整定 `amax`/`vmax` 必须用 SCurve 模式，且要等航点切换。

## 典型整定场景

### 场景 1：落点误差始终 > 10 mm

**先确认是不是静摩擦**。看遥测：球停住不动，但 `fb` 持续输出某个值 →
就是静摩擦钉住了，此时**再调 Kp/Kd 都没用**（残差 = θ_stick/Kp 是硬下限）。

按前面的表提高 `dith_amp` 并降低 `dith_freq`，推荐先试 `1.44° @ 1 Hz`。
观测 `ball_hold_monitor.html` 的误差直方图是否从 13 mm 附近收拢到 0。

### 场景 2：末端过冲 / 来回震荡

震荡频率决定该动哪一项：

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 慢速大幅摆动 | Kd 不足 | 提高 `kd`（0.035 → 0.05） |
| 快速小幅抖动（>5 rad/s） | 反馈饱和引发的极限环 | 提高 `fblim` 或降 `kd` |
| 单向持续漂移 | 水平点未标定 | 调 `lvl_bias`，或先做辨识 |

**极限环的判据**：看遥测 `fbc` 位。若长期为 1，说明 `Kd·v` 顶穿了 `fblim`
（实测 `Kd·v = 1.41°` vs `Kp·e = 0.57°`，合计超 ±2°），这时降 `kd` 比提 `fblim` 更对。

### 场景 3：响应太慢

提高 `amax`（200 → 300）和 `vmax`（90 → 120），**必须在 SCurve 模式下改**。

但先检查是不是执行器跟不上：看遥测 `lag`（指令角与实测角之差）。
`SERVO_KP=3` 时实测 lag RMS 0.92°，这个滞后在 3.3 rad/s 上独占 47° 相位裕度。
如果 lag 大，提高 amax 只会让跟踪误差更大，治不了根。

### 场景 4：抖动一直不触发

按顺序查这四个条件（全部满足才起振）：

1. `dith_amp > 0` — 是不是被设成 0 了
2. 剖面已走完 — 遥测 `act=0`
3. `|误差| > dith_minerr` — 球是不是已经进判据了
4. `|v| < dith_maxspd` 持续 `dith_dwell` 秒 — 球是不是还在滚

遥测 `dth` 位直接告诉你抖动是否正在注入。

## 安全边界

每一项的上下界都由物理约束推出，不是拍脑袋。**越界一律拒绝并回报，不做静默钳位**
——静默钳位会让人以为设进去了。

三条最关键的硬约束：

1. **`fblim` + 前馈峰值 < 5.2°**（查表在软限位 20..430 cnt 的物理可达角是
   −5.345°..+5.236°）
2. **`2π·dith_freq·dith_amp < 240 deg/s`**（输出斜率限制，否则抖动被削成三角波）。
   当前上界组合 `2Hz × 2.0°` 只需 25 deg/s，余量充足
3. **`asin(amax/K_G) + fblim < 5.2°`**（前馈与反馈叠加后不许顶限位）

## 掉电即失效

**热更只改内存，不写 flash。** 这是刻意的——整定出来的值必须回填源码并提交，
才算数。

整定完点整定台的 **导出为 C**，它生成可直接粘贴的完整字段名：

```c
/* 由 ball_tune.html 导出 2026-07-31 20:15 */
/* --- 反馈 --- */
.kp_deg_per_mm = 0.047110f,          /* 位置增益 deg/mm */
.kd_deg_per_mm_s = 0.035330f,        /* 速度增益 deg/(mm/s) */
```

粘回 `app/app_ball_scurve_task.c` 的 `H3S_SCURVE_CONFIG` 初始化块。

## 未验证事项

以下两点我只做了编译验证，**没有实机确认**，第一次使用时请留意：

1. **热更与遥测的串口争用**。遥测已占 UART 89%（52 字段 @ 50 ms = 10240 B/s，
   容量 11520 B/s），余量很薄。`AppBallTune_Poll()` 的回显是否会挤掉遥测字节，
   需要实测。若发现遥测行截断，先降遥测频率再整定。

2. **抖动缺口的修正效果**。上面 `1.44° @ 1 Hz` 的推荐值是按一阶位置环模型算的，
   实际衰减还受步进离散步长、机械间隙影响。以 `ball_hold_monitor.html` 的
   误差直方图为准，不要相信计算值。
